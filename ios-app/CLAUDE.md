# CLAUDE.md — ios-app/

## Commands

All commands run from `ios-app/`:

```bash
# Development
npx expo run:ios -d           # Build + run on connected physical device
npx expo run:ios              # Build + run on simulator

# Native regeneration (required after app.config.ts or native module changes)
npx expo prebuild --clean     # Wipes ios/ and android/, regenerates from config

# Type check (no test framework — verification is manual + tsc)
npx tsc --noEmit

# OTA (after a 1.0.x binary with expo-updates is live on the App Store)
eas update --channel production --message "..."
```

## Stack

**Framework**: Expo + React Native (New Architecture, Fabric/JSI enabled)
**Routing**: expo-router (file-based, `app/`)
**Engine**: Hermes
**Data**: tRPC client (typed against `app/` backend) + TanStack Query
**Real-time**: Agora RTC (custom native module in `modules/agora-viewer`)
**Payments**: Stripe React Native (Apple Pay)
**Auth**: JWT stored in `expo-secure-store`
**OTA**: EAS Update (channel `production`, runtime version policy `appVersion`)

## Directory Tree

```
ios-app/
├── app/                        # expo-router file-based screens
│   ├── _layout.tsx             # Root stack + providers
│   ├── (auth)/                 # Unauthenticated stack (welcome, login, register)
│   ├── (tabs)/                 # Authenticated tabs (index, lives, orders, profile)
│   ├── live/[liveId].tsx       # Dynamic live stream screen
│   └── onboarding.tsx          # Post-signup profile setup
├── src/
│   ├── components/             # Reusable view components (LiveCard, OrderCard, live/*)
│   ├── contexts/AuthContext.tsx
│   ├── lib/                    # trpc, auth, agora, queryClient, config
│   └── providers/              # StripeProvider, TRPCProvider
├── modules/
│   └── agora-viewer/           # Custom Expo native module (Swift) for Agora video
├── assets/                     # fonts/, images/
├── ios/                        # Generated by `expo prebuild` — DO NOT edit by hand
├── app.config.ts               # Expo config (plugins, version, entitlements, env)
└── eas.json                    # EAS build + update channels
```

## Conventions

- **Styling**: `StyleSheet.create` only. No Tailwind, no semantic tokens. Hex colors inline (alignment with web design tokens is deferred — see `features/`).
- **tRPC calls**: allowed directly in screen `.tsx` files. The web's `<Page>.tsx` / `<Page>.hooks.ts` split does **not** apply here.
- **Routing**: file-based via expo-router. New screen = new file in `app/`. Layouts (`_layout.tsx`) wrap nested routes.
- **Auth gating**: `(auth)` group = unauthenticated, `(tabs)` group = authenticated. Logic lives in `AuthContext` + the root `_layout.tsx`.
- **Config plugins** (`app.config.ts`): only list packages that ship `node_modules/<pkg>/app.plugin.js`. Verify with `ls` before adding. Packages without `app.plugin.js` are autolinked automatically — adding them to `plugins` will error at prebuild.
- **Native modules**: live in `modules/<name>/` as Expo Module packages with their own `expo-module.config.json`, `ios/` Swift sources, and `src/` TS bindings.
- **Env vars**: read via `expo-constants` (`Constants.expoConfig.extra.<key>`), declared in `app.config.ts > extra`. `EXPO_PUBLIC_*` vars are baked at build time.

## Gotchas

- **Stale `ios/` after installing a native module** — `npm install` of a package with native code does NOT update `ios/Podfile` or `Pods/`. Linker errors like `Undefined symbols ... facebook::react::Sealable` follow. Fix: `npx expo prebuild --clean`.
- **`app.config.ts` plugin config drifts from runtime config** — plugin args (e.g. Stripe `merchantIdentifier`) are baked into `.entitlements` at prebuild time. Changing only `extra.*` won't update the entitlement. Always re-prebuild after touching plugin args.
- **Web/iOS Stripe key mismatch** — `pk_test_*` on one side and `pk_live_*` on the other produces "No such setupintent" errors silently. Both sides must match the server's secret key environment.
- **Apple Pay merchant ID** — must match across three places: `app.config.ts` Stripe plugin config, `StripeProvider` runtime prop, and the merchant registered + certified in Apple Developer Portal. Any mismatch → "Payment has been canceled" with no explanation.
- **iPad provisioning** — automatic signing cannot register a new device by itself. Add the iPad UDID at developer.apple.com → Devices before `npx expo run:ios -d`.
- **`supportsTablet: false` ≠ iPad-blocked** — apps still install on iPad in iPhone-compatibility mode, and Apple reviewers WILL test on iPad. All flows must work there.
- **OTA runtime version pinning** — `runtimeVersion.policy: "appVersion"` ties updates to the app version. A 1.0.3 binary cannot receive an update published against 1.0.2 (intentional — prevents shipping JS that references a native module the binary lacks).

## What NOT to do

- Do not edit anything inside `ios/` — it is regenerated by `expo prebuild`.
- Do not add a package to `app.config.ts > plugins` without verifying `app.plugin.js` exists in its npm package root.
- Do not call `fetch` directly — use `trpc` from `src/lib/trpc.ts`.
- Do not import design tokens or Tailwind classes from `app/client/` — iOS uses `StyleSheet.create` only.
- Do not bump the Expo SDK or React Native version mid-feature — it triggers prebuild churn and Podfile regeneration.
